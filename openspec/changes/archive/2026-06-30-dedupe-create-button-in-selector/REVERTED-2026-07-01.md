# REVERTED 2026-07-01

This change was archived on 2026-06-30 and then reverted on 2026-07-01
(commit `5dea8679`, on branch `feature/JNG-6391_Test_Data-TestId`).

## Why

The originally-shipped change hid the form-opening Create toolbar
button entirely when the table was rendered inside an AddSelector /
SetSelector dialog overlay. Framed as a `data-testid` dedupe, it was
in reality a UX / product decision that removed a modeled affordance
from the generated DOM based on mount context.

On review it was decided that:

1. Removing a modeled action from the DOM based on runtime mount
   context is out of scope for a test-id hygiene ticket (JNG-6391).
2. The underlying MUI-portal double-mount problem (same table
   rendered twice: once on the page, once inside the dialog) is
   better solved by per-mount test-id prefixing than by DOM removal.
3. If, in the future, JUDO users want the Create button suppressed
   inside selectors as a UX default, that belongs in a dedicated
   product ticket with its own escape-hatch template parameter (e.g.
   `showCreateButtonInSelector`).

## What was reverted

The revert commit removed all of the following from generated code:

- `hiddenInSelectorMode?: boolean` field on
  `ToolBarActionProps<T>` in `utilities/table.ts.hbs`.
- The template block in
  `containers/components/table/index.tsx.hbs` that emitted
  `hiddenInSelectorMode: true` for
  `button.actionDefinition.isOpenCreateFormAction`.
- The `.filter((toolBarAction) => !(<selectorFlag> && toolBarAction.hiddenInSelectorMode))`
  chain in both `LazyTable.tsx.hbs` and `EagerTable.tsx.hbs`.
- The `isSelectorTable` destructure in `EagerTable.tsx.hbs`
  (declared on the props interface pre-`594a98f9` but never read).

Snapshots for the 4 affected files (2 in ActionGroupTest, 2 in
ActionGroupTestPro) were regenerated via
`-DforceSnapshotOverwrite=true` and the full itest suite (6 itests /
14 actor sub-modules) built green.

The `table-toolbar-rendering` capability under `openspec/specs/` was
deleted as part of the same commit, since its two requirements
(Create-button suppression in this change + testid-strip in the
partially-reverted `2026-06-30-testid-row-actions-unique-per-row`)
are both no longer part of the shipped behavior.
