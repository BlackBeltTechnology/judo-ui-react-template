# Data Model Code Generation

## Purpose

Generates TypeScript type definitions, service interfaces, and API integration code from UI data model elements. The data model layer provides the type-safe foundation that all generated pages, containers, and actions operate on. While the REST service layer is generated by a separate template (`judo-ui-typescript-rest-template`), this template generates the service usage patterns, query customizers, and data masks.

## Requirements

### Requirement: Service Class Resolution

The generator SHALL resolve and instantiate a service class for each page's API communication.

Service classes SHALL be generated by the REST template and imported by reference. Service implementations SHALL be instantiated with the Axios provider.

#### Scenario: Page service instantiation

- **WHEN** a page is bound to a data element with a `ClassType` target
- **THEN** the service class is resolved, imported, and instantiated with `judoAxiosProvider`

**Key Helpers**: `UiPageHelper.getServiceClassForPage()`, `UiPageHelper.getServiceImplForPage()`, `UiPageHelper.getRelatedServicesForPage()`

---

### Requirement: Query Customizer Construction

The generator SHALL produce query customizer objects for data loading operations.

A query customizer SHALL specify: mask (which fields to fetch), sort order, filter criteria, and pagination. `processQueryCustomizer()` utility SHALL transform the customizer before sending. The mask SHALL be computed from visible columns/fields plus additional mask attributes.

#### Scenario: Table data loading with query customizer

- **WHEN** a table loads data via a refresh action
- **THEN** the query customizer includes the column mask, sort parameters, filter criteria, and page size

**Key Helpers**: `UiPageContainerHelper.getMaskForTable()`, `UiPageContainerHelper.getMaskForLink()`, `UiPageContainerHelper.getMaskForView()`, `UiPageContainerHelper.serializeMaskForTable()`, `UiPageContainerHelper.serializeMaskForLink()`, `UiPageContainerHelper.serializeMaskForView()`

---

### Requirement: Data Mask Generation

The generator SHALL produce nested object structures specifying which attributes to fetch from the API.

Table masks SHALL include all column attribute types plus `additionalMaskAttributes` plus `additionalMaskRelations`. Link masks SHALL include all parts attribute types plus `additionalMaskAttributes`. View masks SHALL include all input attribute types plus relation display attributes.

#### Scenario: View mask with relations

- **WHEN** a view page has inputs and relation links
- **THEN** the mask includes all input attribute types and relation display attributes

---

### Requirement: Enumeration Type Handling

The generator SHALL import and use enumeration types from the REST-generated model layer.

Enum display values SHALL be internationalized via i18n keys. Enum options for combos, radios, and toggle bars SHALL reference `EnumerationMember` values. Table columns with enum type SHALL get `singleSelect` column type with value options.

#### Scenario: Enum in table column

- **WHEN** a table column is bound to an `EnumerationType` attribute
- **THEN** the column is configured as `singleSelect` with enum member options
- **AND** enum labels are resolved via i18n keys

**Key Helpers**: `UiPageHelper.getEnumDataTypesForPage()`, `UiPageContainerHelper.getEnumDataTypesForContainer()`

---

### Requirement: Signed ID Handling

The generator SHALL use `__signedIdentifier` for concurrency control on entities.

The signed ID SHALL be fetched with every read operation. The signed ID SHALL be passed back on update/delete to detect concurrent modifications. The server SHALL reject stale signed IDs with a conflict error.

#### Scenario: Concurrent modification detection

- **WHEN** an entity is updated
- **THEN** the signed ID from the last read is sent with the update request
- **AND** a stale signed ID results in a conflict error

**Key Helpers**: `UiPageHelper.pageHasSignedId()`

---

### Requirement: Draft/Dirty State Management

The generator SHALL manage draft and dirty state for entities.

Created (unsaved) entities SHALL have a draft identifier prefix. `draftIdentifierPrefix` constant SHALL mark unsaved entities. Dirty state SHALL be tracked for navigation confirmation ("unsaved changes" dialog).

#### Scenario: Unsaved changes detection

- **WHEN** a user edits a view page and navigates away
- **THEN** the dirty state is detected and a navigation confirmation dialog is shown

**Generated Utilities**: `src/services/data-api/common/utils.ts`, `src/hooks/useNavigationConfirmation.tsx`

---

### Requirement: API Import Generation

The generator SHALL compute and generate TypeScript imports for model types, stored types, and query customizers per page.

Only used types SHALL be imported to keep bundles small.

#### Scenario: Optimized imports

- **WHEN** a page references specific `ClassType` elements and their attributes
- **THEN** only the referenced types are imported in the generated page

**Key Helpers**: `UiPageHelper.getApiImportsForPage()`, `UiImportHelper.getTableAPIImports()`, `UiImportHelper.getLinkAPIImports()`, `UiPageContainerHelper.getContainerApiImports()`

---

### Requirement: Behaviour-Driven Capability

The generator SHALL use `ClassType.behaviours` to determine which CRUD operations are available on a page.

`REFRESH` SHALL enable the refresh action. `UPDATE` SHALL enable the update action. `DELETE` SHALL enable the delete action. `TEMPLATE` SHALL enable the get-template action for create forms. `VALIDATE_UPDATE` SHALL enable server-side update validation.

These flags SHALL propagate to page-level action availability.

#### Scenario: Entity with limited behaviours

- **WHEN** a `ClassType` has only `REFRESH` and `DELETE` behaviours
- **THEN** the page has refresh and delete actions but no update action

---
