# Architecture

## Pattern: Model-Driven Code Generator
The project follows a **model-driven architecture (MDA)** pattern where a JUDO UI Model (EMF/XMI) is transformed into a complete React/TypeScript frontend application through two generation phases.

## Generation Pipeline

```
┌─────────────┐    ┌──────────────────────┐    ┌─────────────────────┐    ┌──────────────────┐
│ .model file │───>│ Phase 1: REST/TS     │───>│ Phase 2: React UI  │───>│ React App        │
│ (EMF/XMI)   │    │ (typescript-rest-    │    │ (this project)     │    │ (target/         │
│             │    │  template)           │    │                    │    │  frontend-react/) │
└─────────────┘    └──────────────────────┘    └─────────────────────┘    └──────────────────┘
                   Generates:                  Generates:
                   - API types                 - Pages, Dialogs
                   - Service interfaces        - Containers, Widgets
                   - Axios implementations     - Routing, Auth, i18n
                                               - Layout, Theme
```

## Layers

### 1. Template Registry Layer (`ui-react.yaml`)
- Central configuration mapping templates to output files (1170 lines)
- Each entry specifies: `templateName`, `pathExpression`, optional `factoryExpression`, `templateContext`, `conditionExpression`
- **Static templates**: Single output file (e.g., `App.tsx`, `package.json`)
- **Factory templates**: Multiple output files generated per model element (e.g., one page per `PageDefinition`, one container per `PageContainer`)
- SpEL expressions reference helper methods: `#getPagesForRouting(#application)`, `#containerPath(#self)`

14 Java classes providing logic callable from Handlebars templates:

| Helper | Lines | Responsibility |

| `UiPageContainerHelper` | 769 | Container layout, paths, component names, action definitions |
| `UiWidgetHelper` | 623 | Widget rendering, size calculation, alignment, visual element traversal |
| `UiPageHelper` | 612 | Page routing, navigation, data access patterns, page classification |
| `UiActionsHelper` | 577 | Action generation, button/operation logic, CRUD patterns |
| `UiTableHelper` | 428 | Table/grid generation, filtering, sorting, column definitions |
| `UiI18NHelper` | 415 | Internationalization key generation, translation management |
| `UiGeneralHelper` | 239 | Naming utilities, path generation, annotations |
| `UiImportHelper` | 164 | TypeScript import management for MUI components |
| `UiPandinoHelper` | 143 | Pandino service registration/customization hooks |
| `ReactStoredVariableHelper` | 118 | Thread-local context for template parameters |
| `UIMenuHelper` | 90 | Navigation menu structure |
| `UiNPMHelper` | 44 | NPM/pnpm dependency management |
| `UiSecurityHelper` | 33 | Security-related helpers |
| `MaskEntry` | 73 | Data mask serialization for API queries |

### 3. Template Layer (Handlebars)
321 `.hbs` template files in `judo-ui-react/src/main/resources/actor/` organized to mirror the generated React app structure:

- **Root configs**: `package.json.hbs`, `biome.json.hbs`, `vite.config.ts.hbs`
- **App shell**: `src/App.tsx.hbs`, `src/routes.tsx.hbs`, `src/main.tsx.hbs`
- **Pages**: `src/pages/index.tsx.hbs` (factory — one per routed page)
- **Dialogs**: `src/dialogs/index.tsx.hbs` (factory — one per dialog page)
- **Containers**: `src/containers/container.tsx.hbs` (factory — one per container)
- **Components**: `src/components/` (shared UI components)
- **Layout**: `src/layout/` (drawer, header, footer, bottom menu)
- **Fragments**: `src/fragments/` (partial templates for composition via `{{> fragment.hbs}}`)

### 4. Generated Application Layer
The output React app follows a layered architecture:
- **Pages** — Route-level components with business logic, state management, action handlers
- **Dialogs** — Modal page components (same structure as pages)
- **Containers** — Pure UI components (layout, widgets, form structure)
- **Components** — Reusable widgets (tables, inputs, dialogs, navigation)
- **Services** — REST API layer (generated by Phase 1)
- **Customization hooks** — Pandino-based extension points for runtime overrides

## Key Abstractions

### Template Context (`#self`, `#application`)
Templates receive context objects from the model:
- `#application` — Root `Application` model element
- `#self` — Current element in factory expressions (e.g., a `PageDefinition` or `PageContainer`)
- Custom context via `templateContext` entries in `ui-react.yaml`

### Pandino Extension Points
Generated apps expose customization interfaces via Pandino (OSGi-style DI):
- `ROUTE_*_INTERFACE_KEY` — Route-level customization
- `*_ACTIONS_HOOK_INTERFACE_KEY` — Action behavior overrides
- `CUSTOM_VISUAL_ELEMENT_INTERFACE_KEY` — Custom component implementations

### Action Definitions
Model actions are classified and handled differently:
- `CallOperationActionDefinition` — Backend API calls
- `OpenPageActionDefinition` — Navigation to pages
- `OpenFormActionDefinition` — Open form dialogs
- `OpenSelectorActionDefinition` — Open selector dialogs
- CRUD actions: refresh, create, update, delete, export

## Entry Points
- **Generator entry**: `judo-ui-generator-maven-plugin` reads `ui-react.yaml`, loads helpers via `@TemplateHelper` annotation scanning, evaluates SpEL expressions, and renders Handlebars templates
- **Generated app entry**: `src/main.tsx` → `src/App.tsx` → React Router → Page components
